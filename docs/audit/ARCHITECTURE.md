## 1. Sažetak sistema

Repozitorij je multi-app proizvod sa tri odvojeno instalirana npm paketa:

| Dio | Implementacija | Glavna odgovornost |
|---|---|---|
| Backend | NestJS 11, TypeScript, Prisma 7, PostgreSQL (`@prisma/adapter-pg`) | REST API, poslovna pravila, persistencija, Socket.IO, scheduled jobs |
| Web | React 18, TypeScript, Vite, React Router 6 | Javna salon stranica, klijentski booking/account tokovi, admin i stylist portali |
| Mobile | Expo SDK 57, React Native 0.86, Expo Router, TypeScript | Klijentski i stylist mobilni tokovi, push, APK update |
| Persistence | PostgreSQL + dijeljeni upload direktorij | Relacioni podaci, lokalno/host-mount fajl skladište |
| Opcionalni infra | Redis je external service; backend Compose koristi ga za Socket.IO adapter i opcionalni HTTP rate limit | Queue i distributed-lock workload nisu implementirani |

Nema root `package.json`; `backend/`, `frontend/` i `mobile/` imaju zasebne `package-lock.json` fajlove. Aktivna DB šema je PostgreSQL. Prisma `PrismaService` eksplicitno odbija svaki `DATABASE_PROVIDER` osim `postgres`, iako dependency set još sadrži MariaDB adapter/dependency ostatke. U aktivnom `backend/prisma/migrations/` postoje PostgreSQL baseline migracija i naredna blog SEO migracija.

> Runtime topologija, živi DB sadržaj, eksterni reverse proxy, secret manager, TLS, backup i produkcijski Redis ACL nisu provjereni iz ovog repo audita.

## 2. Runtime granice i request putanja

### HTTP/API

1. `backend/src/main.ts` kreira Nest Express app, registruje JSON exception filter, Decimal→Number interceptor i globalni `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`).
2. App-wide `APP_GUARD` je `JwtAuthGuard`. Endpointi moraju eksplicitno koristiti `@Public()` da zaobiđu JWT. Prisustvo `@Roles()`/`RolesGuard` dodaje role policy na izabrane rute; ne zamjenjuje service-level ownership provjere.
3. `JwtStrategy` poziva auth validaciju koja provjerava da je korisnik aktivan i čita trenutne role iz baze. Web JWT se čuva u `localStorage`; mobile access token u `expo-secure-store`.
4. DTO-jevi sa `class-validator` dobijaju whitelist validaciju. Query/body parametri definisani samo kao inline TS tipovi ili `string` nemaju nužno istu runtime validaciju.
5. Prisma runtime koristi `PrismaPg({ connectionString: DATABASE_URL })`; seed i media-storage migration runner koriste isti adapter. Zaključani `pg-connection-string` parser prepoznaje `sslmode=verify-full`, učitava `sslrootcert` fajl i ne isključuje CA ni hostname verifikaciju. Compose taj host CA montira read-only na `/etc/ssl/certs/coolify-ca.crt`; postojeći `DATABASE_URL` env passthrough već prenosi query parametre bez izmjene application koda. Parser je provjeren lokalno sa synthetic CA fajlom, ne sa stvarnom DB konekcijom. Repo ne uključuje produkcijsku DB uslugu u Compose.

Ključni entrypoint-i: [AppModule](../../backend/src/app.module.ts), [main.ts](../../backend/src/main.ts), [PrismaService](../../backend/src/prisma/prisma.service.ts), [Prisma config](../../backend/prisma.config.ts).

### Realtime

`EventsGateway` koristi Socket.IO root namespace. Konekcije bez credentials ostaju u `public` room-u; token se validira u handshake middleware-u, a aktivni korisnik i trenutne role čitaju se iz baze prije dodjele `user:<id>`, `admin` ili `stylists` rooms. Nevažeći token, nepostojeći/deaktivirani korisnik ili DB greška odbija handshake umjesto da konekciju degradira na anonymous. `emitToUser`, `emitToAdmins` i `emitToStylists` ciljaju room; `emitToAll` je globalni `server.emit`. `SOCKET_IO_MULTI_INSTANCE` odnosi se na replike ovog backenda (ne na druge aplikacije koje dijele Redis). Produkcijski Compose ga podrazumijeva na `true`; tada je obavezan `SOCKET_IO_REDIS_URL` sa dedicated, non-default ACL username/password. `false` bira procesni in-memory adapter i ne smije se kombinovati s Redis URL-om. `RedisIoAdapter` koristi Redis Pub/Sub i dobija `SOCKET_IO_REDIS_CHANNEL_PREFIX` kao adapter key; podrazumijevani prefix je `beauty-salon-v2:<NODE_ENV>` (Compose production: `beauty-salon-v2:production`). Sve replike iste aplikacije/okruženja koriste isti prefix, dok druge aplikacije i okruženja trebaju zaseban prefix i ACL channel scope. U ovom repou se samo backend priključuje na external `db_net` i `redis_net`; Redis host je korisnički prijavljeni `redis-core:6379`. URL koristi `redis://` za non-TLS ili `rediss://` ako Redis TLS radi. Lokalni development bez Redis URL-a ostaje na in-memory adapteru. Trenutna implementacija očekuje jedan kompatibilan Redis endpoint; native Redis Cluster/Sentinel konfiguracija nije dodana. TLS transport za Socket.IO i HTTP rate-limit Redis klijente sada se podešava preko `REDIS_TLS` i opcionalnog `REDIS_CA_CERT_PATH`; URL sa `rediss://` također uključuje TLS. Produkcijski Compose podrazumijeva `REDIS_TLS=true`, postavlja CA putanju `/run/secrets/redis-ca.crt` i read-only montira host `/data/coolify/ssl/redis-core/redis-ca.crt`. CA se prosljeđuje node-redis TLS opcijama bez isključivanja certifikatske verifikacije. Ova konfiguracija i putanja potvrđene su samo kroz source i mocked testove; stvarni CA sadržaj, TLS handshake, ACL, DNS/mreža i deployment nisu testirani. Socket.IO connection dijagnostika sada loguje samo allowlisted kategoriju greške, poznati error code i type; originalna poruka, stack i Redis URL namjerno se ne loguju. Vidi [gateway](../../backend/src/events/events.gateway.ts), [Redis adapter](../../backend/src/events/redis-io.adapter.ts) i [runtime config](../../backend/src/events/socket-io-runtime-config.ts).

`EventsGateway` odbija autentificirani token bez numeričkog `exp` i zatvara socket kada token istekne. `UsersService` active-status/role izmjene i `StylistsService` profile/role eligibility promjene pozivaju disconnect svih sockets za korisnika nakon DB izmjene; `STYLIST` room pri handshake-u zahtijeva active profil. Sa Redis adapterom, room disconnect se emituje na sve instance. Kada pub/sub veza u procesu prelazi u reconnect, lokalne sockets se zatvaraju i adapter odbija nove handshakes dok obje Redis veze nisu spremne. Ovo je provjereno samo s mock Redis klijentima; cross-instance delivery, Redis outage/failover i stvarni deployment nisu testirani. Password-change JWT revocation nije implementiran.

`SettingsService.set` šalje globalni `settings:updated` sa vrijednošću samo za ne-secret `PUBLIC` ključeve; `PRIVATE`/secret izmjene šalju key-only invalidaciju admin room-u, nakon čega admin klijent ponovo čita preko guarded HTTP API-ja. `SalonService.update` šalje samo `{key: 'salon'}` kao `salon:updated` invalidaciju, umjesto punog salon/holiday objekta; caller i dalje dobija HTTP rezultat. Live Socket.IO integration test pokriva transport, rooms, event payload-e, revocation i expiry uz mock Prisma provider, ne stvarnu bazu. CORS allowlist, browser behavior i deployment ostaju nevalidirani (SEC-06).

### Client reconnect policy

Web and mobile providers use a manual retry controller with Socket.IO Manager reconnection disabled. Server/transport disconnects and every `connect_error` except exact `Unauthorized` retry with 1s, 2s, 4s, then a 5s cap; a successful connection resets the delay. Each retry reuses the current token, so the backend handshake re-reads current DB roles/status. `Unauthorized` stops retries and disconnects locally without clearing the stored token or logging out. Node regression suites pass 6/6 in each app; they do not replace browser/device or live Redis/DB/deployment validation.

### Rezervacija (klijentski self-service)

1. Web/mobile traži aktivne servise i availability; booking UI zahtijeva prijavu, onboarding, email/phone podatke i gender.
2. `ReservationCreateService` ponovo provjerava klijentski status, odabrane servise/gender, penalizaciju, availability slot i client-day booking policy.
3. Upisuje `Reservation` u `PENDING`, zatim service-item i stylist-response redove. Odabrani stilisti dobijaju notifikaciju; potom se po potrebi redeem-uju loyalty bodovi, query-uje puni response i emituju događaji.
4. Stylist lock/accept vodi do potvrđenog termina; attendance policy, `IN_PROGRESS`, `AWAITING_DAILY_LOG`, completion/cancellation/no-show su zasebni tokovi. Status transition helper opisuje FSM u `reservations/constants.ts`.
5. Nakon rada, daily-log zapis vodi cijenu/tip, slike, eventualni dug, KIF unos i loyalty earn/redeem.

Ovaj redoslijed opisuje kod, ne garantuje transakcijsku atomarnost. Kritične djelimične-upise i concurrency kandidate dokumentuje [FINDINGS.md](FINDINGS.md).

### Dnevnik i finansije

- `DailyLogEntry` je izvor evidencije odrađene usluge; `DailyLogImage` veže upload uz `isBefore`/`isAfter`. Public before/after query radi samo kad je aktivna auto-publish kategorija i traži linked client, completed/undeleted `SERVICE`, dva različita before/after image ID-a i aktivan `client-media-publication-v1` consent za obje strane; public route vraća samo consent derivative URL-ove, bez service/date/client metapodataka.
- Loyalty mutation helper serijalizuje saldo promjene account row lock-om i conditional `updateMany`, a tier se računa dok je isti account zaključan. Reservation debit, tier, ledger i marker dijele booking transaction; manual redeem/adjust koriste UUID idempotency key, a dnevni-log redeem veže debit/ledger/marker za entry/account transakciju. Reversal bilježi primijenjenu ADJUST promjenu per original ledger row; daily-log earn/recompletion koristi completion-generation key.
- Loyalty money order: requested discount se računa Decimal-om i zaokružuje half-up na 2 decimale; redeem bodovi su floor(requested discount / KM-per-point); pohranjeni popust je minimum requested amount-a i zaokružene vrijednosti stvarno potrošenih bodova. Daily-log cijena prednost daje spremljenim `DailyLogEntryServiceItem.unitPrice` vrijednostima; catalog cijena je fallback. Read-only `GET /api/loyalty/reconciliation` za OWNER/SYSTEM_ADMIN koristi jedan Repeatable Read snapshot i prijavljuje negativne salde, saldo-vs-ledger i reservation/daily-log marker/REDEEM mismatch-e bez repair/write operacija.
- `DailyLogService.complete()` source path row-locka/re-čita log i u jednoj transakciji usklađuje completion generation, validnu vezanu rezervaciju, KIF `IncomeBookEntry`, loyalty earn ledger i deduplicirani completion outbox. `IncomeSyncService.addEntryFromDailyLog(id, tx)` koristi isti tx client; završeni retry reconciliuje lokalne durable efekte.
- Auto-KIF `IncomeBookEntry.dailyLogEntryId` je globalno unique (one-to-one Prisma relacija), ne samo unique unutar period knjige; migration preflight aborta na legacy duplikatima. Debt payment se knjiži odvojenim `IncomeBookManualEntry` putem.
- Receipt/email/realtime dispatch slijedi commit i ima cron retry; DB notification dedupe je event-scoped, dok vanjski provider delivery ostaje at-least-once. CI run `40137519486` passed generated Prisma/schema/migrations/build/full unit suite i DB-backed BIZ-03 E2E na disposable PostgreSQL-u; bez production/shared DB ili deployment provjere.
- `ClientDebt` vezuje klijenta, stilistu i izvorni reservation/daily-log/manual entry; zatvaranje duga kreira debt-payment zapis i KIF manual income.
- `ExpenseBook` sadrži expenses, kategorije, template fields, attachments i lock events. `IncomeBookManualEntry` ima before/after audit payload.
- DB iznosi su `Decimal`, a globalni interceptor serijalizuje ih u JSON number radi postojećih klientskih tipova; krajnje poslovne aritmetičke agregacije i concurrency i dalje treba testirati.

### Content, notification i release

- Public blog list/detail uvijek filtriraju objavljene postove; public slug response sanitizes HTML with the backend allowlist before `PublicBlogPost` inserts it, and create/update sanitize before persistence. Admin list/draft/comment-moderation reads su role-guarded; browser/runtime/deployment verification za SEC-08 još nije izvršena.
- Uploaded SVG brand logo više se ne ubacuje kao inline markup; web component koristi URL kao CSS mask image da sačuva monochrome `svgColor` bez `dangerouslySetInnerHTML`.
- Public review/galerija/before-after su odvojene API surface granice. Web `/galerija` i mobile before/after feed koriste consent-filtered feed; ručno dodavanje client media u Gallery prihvata samo active `CONSENTED_PUBLIC` derivative iz eligibility query-ja, a generic `PUBLIC` upload ne može se koristiti za client image. Separate category-bound upload podržava samo admin/owner-attested non-client salon/product media, normalized to WEBP. Revoke provjerava active consent pri svakom `/api/media/consents/:id/file` čitanju i nema cache-a. Javni avatar je zaseban user-owned opt-in route i ne daje Gallery/ads/social-media permission.
- API-02 public blog/comment, service/stylist catalog (including category/subcategory and per-stylist service lists) and review endpoints use bounded pages and stable ordering; nested catalog relations are capped at 50 per parent. Web/mobile/admin/finance clients use page helpers and cap legacy arrays at 1,050 items. Analytics filters are date-only and range-validated; dashboard month buckets/relative ranges use UTC calendar values, and omitted client/stylist ranges use UTC calendar today for a rolling 12-month window. Availability is capped by date interval and per-request lookup concurrency. The non-random daily-log gallery is bounded by page/offset; random mode uses `DailyLogEntry.randomKey` (`random_key`) plus an index and reads a circular window of at most 50 instead of loading every eligible ID. Eligibility predicates can still make PostgreSQL inspect additional rows.
- HTTP public/admin routes use a global 60-second Redis-backed request limiter with the approved per-route user/IP buckets. It has a dedicated HTTP Redis URL/prefix/ACL, separate from Socket.IO; unavailability fails open with a warning. Exactly one proxy hop is trusted for client-IP extraction. This is a source design, not production-load evidence; synthetic PostgreSQL CI does not exercise actual Redis.
- App notification se čuva u DB, zatim emituje korisniku i opciono šalje Expo push/SMTP prema preferencama i sistemskom flagu. Kampanje se šalju sinhrono kroz recipient loop.
- APK release JSON daje `versionCode`, `minSupportedVersionCode`, `forceUpdate`, `apkUrl` i SHA-256; mobile downloader validira hash prije installer intent-a.
